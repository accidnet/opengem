# Gmail 연결과 반복 메일 확인

OpenGem의 이메일 연결은 모든 에이전트가 공유하는 전체 설정입니다. 현재 Gmail의 받은편지함 읽기를 지원합니다. 메일 전송·삭제·읽음 표시 변경·외부 캘린더 등록 권한은 요청하지 않습니다.

## 처음 연결하기

1. [Google Cloud Console](https://console.cloud.google.com/)에서 개인용 프로젝트를 만들고 **Gmail API**를 사용 설정합니다.
2. **Google Auth Platform**에서 동의 화면과 사용 대상을 설정합니다. 테스트 상태라면 본인 Gmail 주소를 테스트 사용자에 추가합니다.
3. **클라이언트**에서 OAuth 클라이언트를 만들고 애플리케이션 유형으로 **데스크톱 앱**을 선택합니다. 웹 애플리케이션용 클라이언트를 사용하지 않습니다.
4. OpenGem의 **사용자 메뉴 > 이메일 연동**에서 클라이언트 ID와 클라이언트 보안 비밀번호를 입력하고 저장합니다. Google 계정 비밀번호를 입력하는 곳이 아닙니다.
5. **Gmail 연결**을 누르면 시스템 브라우저가 열립니다. 계정을 선택하고 Gmail 읽기 권한에 동의한 뒤 앱으로 돌아옵니다.
6. 연결된 이메일 주소를 확인하고 원하는 에이전트에게 “매시간 새 이메일을 요약하고 일정이 있으면 날짜와 시간을 정리해 줘”라고 요청합니다. 연결 전에 부탁한 업무도 저장되며, 연결을 완료하면 이후 실행에서 다시 시도합니다.

로그인은 5분 안에 완료해야 합니다. 취소하거나 클라이언트 설정을 바꾸면 진행 중인 이전 로그인 응답은 무시합니다. 브라우저에서 권한을 거절했다면 설정에 표시되는 오류를 확인하고 다시 연결합니다.

## 저장과 실행

- 에이전트의 기억, 반복 업무, 실행 결과는 에이전트별로 보관합니다. Gmail 계정 연결만 전역 설정입니다.
- Gmail API 호출과 OAuth 토큰 갱신은 Rust 백엔드에서 수행합니다. 모델과 프론트엔드에 인증 토큰을 전달하지 않습니다.
- 클라이언트 보안 비밀번호와 갱신 토큰은 Windows 자격 증명 관리자, macOS 키체인 또는 Linux Secret Service에 저장합니다. SQLite에는 연결 상태·클라이언트 ID·이메일 주소와 저장소 식별자만 저장합니다. 액세스 토큰은 메모리에만 보관합니다.
- Linux에서는 실행 중인 Secret Service와 잠금 해제된 로그인 키링이 필요합니다. 빌드 시 libdbus 개발 패키지도 필요합니다. 저장소가 없거나 잠겼다면 평문 파일로 우회하지 않고 오류를 표시합니다.
- 연결 해제는 진행 중인 로그인과 메일 읽기를 중단하고 로컬 갱신 토큰을 제거합니다. 클라이언트 설정은 재연결을 위해 유지합니다. Google 계정의 앱 권한 자체를 철회하려면 [Google 계정 연결 관리](https://myaccount.google.com/connections)에서 제거합니다.
- 받은편지함의 새 메일을 읽으며 이미 읽음 처리된 메일도 대상입니다. 첨부파일은 다운로드하지 않습니다. 일반 텍스트 본문을 우선 사용하고 HTML은 텍스트로 변환합니다.
- 본문은 메일당 8,000자로 제한합니다. 2 MiB를 넘는 응답은 메타데이터와 미리보기로 대체합니다. 본문 일부 또는 미리보기만 제공한 메일에는 불완전 표시가 있어 모델이 확정되지 않은 일정을 단정하지 않게 합니다.
- 메일 본문은 외부 자료입니다. 본문 안의 지시를 실행하거나 그 지시로 에이전트 기억·반복 업무를 바꾸지 않습니다. 요약에 필요한 메일 내용은 선택한 모델 제공자에게 전달됩니다.
- 반복 확인은 OpenGem이 실행 중일 때 진행합니다. 앱 종료나 절전 중에는 실행되지 않으며 다시 실행하면 저장된 마지막 확인 위치부터 재개합니다. 운영체제 서비스나 예약 작업은 설치하지 않습니다.

## 연결 오류 해결

- **Gmail API 또는 읽기 권한 오류**: 프로젝트에서 Gmail API가 사용 설정되어 있는지, 본인이 테스트 사용자로 등록되어 있는지, 읽기 권한에 동의했는지 확인합니다.
- **인증 만료**: 설정에서 다시 연결합니다. Google OAuth 앱이 외부 사용자 대상의 Testing 상태라면 Gmail 권한을 사용하는 갱신 토큰은 일반적으로 7일 뒤 만료됩니다. 테스트 상태를 장기 운영에 그대로 사용하면 주기적인 재연결이 필요합니다.
- **네트워크 또는 요청 한도 오류**: 실행 결과에 오류가 남고 마지막 성공 위치는 앞당기지 않습니다. 다음 확인에서 다시 시도합니다.
- **자격 증명 저장소 오류**: 운영체제 계정과 키링 잠금 상태를 확인합니다. 다른 컴퓨터로 SQLite만 복사하면 인증 토큰은 옮겨지지 않으므로 다시 연결해야 합니다.

## 커넥터 계약

다른 이메일 제공자를 추가할 때는 채팅 프롬프트 대신 별도 백엔드 커넥터를 구현합니다. Gmail 구현은 다음 계약을 따릅니다.

- `get_email_settings`: 비밀값 없는 연결 상태 조회.
- `save_email_settings`: 데스크톱 OAuth 클라이언트 설정 저장. 같은 클라이언트에서 빈 비밀번호는 기존 비밀번호 유지.
- `begin_email_login`, `cancel_email_login`, `disconnect_email`: 로그인 시작·취소·로컬 연결 해제.
- `fetch_email_digest_messages`: `{since, until?, pageToken?}`을 받고 `{messages, since, until, nextPageToken, accountEmail}`을 반환. 시간은 Unix 밀리초이며 `since <= receivedAt < until` 경계입니다.
- 호출자는 한 실행에서 `until`을 고정하고 모든 페이지를 처리해야 합니다. 모든 페이지와 보고서 저장이 성공한 뒤에만 확인 위치를 갱신합니다. 실패한 배치의 커서를 앞당기지 않습니다.
