# Codex 시스템 프롬프트 관리

`src/features/chat/prompts/codex.txt`는 Codex 참고 구현의 기본 작업 규칙을 OpenGem 실행 환경에 맞게 재작성한 한국어 프롬프트다. CLI 전용 기능을 그대로 번역하지 않고, 작업 지속성, 저장소 지침, 사용자 변경 보존, 편집·검증·결과 전달 원칙을 반영한다.

## 참고 기준

- 로컬 참고 저장소: OpenGem과 같은 상위 폴더의 `codex/`
- 비교 기준 커밋: `dedd1c386a9bb2b4031d26b0494217a20868fb7a`
- 기본 원본: `codex-rs/protocol/src/prompts/base_instructions/default.md`
- 모델별 보조 원본: `codex-rs/core/gpt-5.2-codex_prompt.md`
- 공식 보조 자료: [Codex Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)
- 최초 반영 이슈: [#10](https://github.com/accidnet/opengem/issues/10)

기본 원본의 작업 지속, AGENTS.md 적용 범위, 검증, 간결한 결과 전달 규칙과 모델별 원본의 작업 트리 보존 규칙을 중심으로 정리했다. 원문의 계획 도구, 승인 모드, 병렬 호출, CLI 출력 형식은 OpenGem의 구현 여부와 무관하게 약속하지 않는다. 기존 프롬프트에 있던 `Read`, `Edit`, `Write`, `Glob`, `Grep`, `Bash` 같은 미제공 도구 이름도 제거했다.

## 프롬프트별 책임

| 구성 요소                           | 책임                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| `codex.txt`                         | Codex 프로필의 협업 태도, 작업 지속, 편집·검증·응답 원칙                         |
| 에이전트별 `agentPrompt`            | 사용자가 선택한 에이전트의 역할과 작업 맥락                                      |
| `tool-use-policy.txt`               | 모든 모델에 공통인 도구 선택, 실행 범위, 결과 처리 규칙                          |
| `tools/prompts/*.txt`와 도구 스키마 | 개별 도구의 실제 기능, 인자, 경로 해석 및 사용 조건                              |
| `promptComposer.ts`                 | 모델 프롬프트, 에이전트 프롬프트, 도구 정책, 현재 환경과 사용 가능한 도구의 합성 |

모델 선택은 기존 `promptProfile: "codex"`와 `resolvePromptProfile()` 흐름을 유지한다. 다른 모델의 `default.txt`, `gpt.txt`는 이 변경에서 수정하지 않는다. 환경 정보나 도구 목록을 `codex.txt`에 복사하지 않아 실행 시점의 실제 상태와 어긋나는 중복 지침을 피한다. 프롬프트는 행동 지침이며 파일 접근 권한이나 승인 기능을 구현하는 보안 경계가 아니다.

## 참고 소스 갱신 절차

1. `codex/` 저장소의 새 커밋과 위 비교 기준 사이에서 기본 원본과 모델별 원본의 변경을 비교한다.
2. 작업 지속, 지침 적용 범위, 편집, Git 보존, 검증, 응답 규칙 중 OpenGem에 필요한 변경을 고른다.
3. 현재 도구 정의와 실행 코드, `tool-use-policy.txt`, `promptComposer.ts`를 확인한다. 미구현 도구·승인·자동 주입 기능은 프롬프트에 추가하지 않는다.
4. 공통 도구 정책은 공통 파일에서, Codex 행동 원칙은 `codex.txt`에서 관리한다. 경로 및 도구 인자 세부사항을 두 곳에 중복하지 않는다.
5. 모델 프로필 매핑과 `?raw` 프롬프트 로딩이 유지되는지 확인하고 `pnpm exec tsc --noEmit`, `pnpm build`, `pnpm lint`를 실행한다.
6. 도구 호출 가능한 테스트 환경에서 아래 동작을 확인하고, 검증한 소스 커밋과 결과를 PR에 기록한다. 실제 모델 호출을 하지 않았다면 정적 검증과 구분한다.

## 동작 확인 사례

- 프로젝트 파일 수정 요청: 관련 코드와 저장소 지침을 확인하고, 기존 변경을 보존하며 수정과 검증까지 진행한다.
- 프로젝트 없는 폴더 확인 요청: 현재 도구 정책의 경로 인자를 사용하고, 존재하지 않는 도구나 자동 권한 승인을 요청하지 않는다.
- 리뷰만 요청: 코드를 임의 수정하지 않고 근거와 위치가 있는 결함을 우선 보고한다.
- 도구 실패 또는 접근 불가: 결과를 지어내지 않고 원인과 가능한 대안을 확인한다.
- 테스트 실행 불가: 구현 완료와 검증 미완료를 구분해 전달한다.
